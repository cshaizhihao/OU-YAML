# 新手教程维护规范

OU-YAML 的教程是产品流程的一部分，不是独立于功能之外的说明文档。任何会改变导航、按钮、字段含义或主要操作顺序的更新，都必须同步检查教程。

## 单一数据源

- 教程版本、流程、步骤和稳定目标位于 `src/guides/registry.ts`。
- 页面通过 `guideTargets` 常量设置 `data-guide-id`，不要直接书写目标字符串。
- 教程状态按用户保存在浏览器本地，流程版本变化时只在帮助按钮提示更新，不重新打断老用户。

## 功能变更要求

1. 修改主要导航或路由时，同步更新教程步骤的 `view`。
2. 修改关键按钮、列表或工作区时，保留原有目标锚点，或同步迁移 `guideTargets`。
3. 新增核心工作流时，为它增加专项教程，并加入教程中心。
4. 操作步骤或含义变化时，更新标题、说明、提示和预计时间。
5. 仅在操作流程变化时提升 `GUIDE_VERSION`（例如 `1.8`）；补丁发布不改变教程版本，教程版本不能高于应用主次版本。
6. 三步主线用 `quickStep` 定位、`advanceOn` 监听成功事件；失败不前进，演示不派发成功事件。
7. 在 README 和 CHANGELOG 中同步用户可见的教程变化。
8. 首页可能显示订阅卡片或创建向导。涉及导入、配置、结果的步骤必须设置 `quickStep`，由首页展开对应向导，不能假设新老用户首页相同。
9. 检查发布摘要不派发 `published`；只有用户确认且服务端发布成功才推进。网站规则添加成功派发 `website-rule-added`，后续步骤仍需等待草稿保存。
10. 任务教程必须覆盖最终使用结果：网站分流包括发布与客户端刷新；故障排查区分来源、节点检测与客户端网络。
11. 已发布编辑使用 `subscription` 路由与明确的订阅 ID，不通过当前项目猜测目标。网站教程先等待 `subscription-rules-opened`，最终等待 `subscription-updated`，不要导航到旧的项目规则页。
12. 订阅编辑不是自动保存，教程不可承诺草稿已保存；未发布离开要触发提示。独立改名不改变内容版本。

## 发布检查

```bash
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`tests/guides.test.ts` 会检查：

- 教程版本格式及与应用版本的兼容关系。
- 教程、步骤和目标 ID 是否唯一。
- 导入、节点、分组、规则、发布和三步主线是否都有教程。
- 每个教程目标是否仍然存在于所属页面。

自动测试通过后，仍应在桌面和手机尺寸各完整走一遍「三步创建第一个订阅」，确认聚光位置、页面滚动、抽屉和底部引导卡片没有遮挡主要操作。小屏教程为主内容保留独立滚动区域，不可用强制点击来绕过遮挡。

`tests/e2e/workflows.spec.ts` 覆盖 390 / 768 / 1440 像素、真实导入发布复制、发布前取消无写入、老用户首页、网站任务教程、排查跳转、中文规则、长列表与键盘排序。新增重要操作须扩充实际交互断言，不能只检查按钮文字存在。
